## Что это за проект

GM Table — прототип виртуального игрового стола для ролевых партий.
Комнаты, сцены, токены, ассеты, рисование и взаимодействие в реальном времени.
Монорепозиторий pnpm:

- `client/`: React, Vite, TypeScript, Zustand, Konva, Socket.IO Client.
- `server/`: Fastify, Socket.IO, Prisma, PostgreSQL.
- `shared/`: общие типы, константы и утилиты; используется обеими частями.

Начни с документации по своей задаче, затем проверь соответствующий код:

- `README.md` — обзор и локальный запуск.
- `docs/ARCHITECTURE.md` — устройство и потоки данных.
- `docs/FEATURES.md` — функциональность.
- `docs/DB_SCHEMA.md`, `docs/WS_PROTOCOL.md` — БД и события.
- `docs/SETUP.md` — локальное окружение.
- `docs/DOCKER.md` — актуальный запуск прототипа в контейнерах.

Некоторые старые инструкции и версии в документации могут отставать от кода.
Версии зависимостей проверяй по package.json и pnpm-lock.yaml.
Текущие Dockerfile используют Node.js 26 и pnpm 10.0.0.

## Docker

Приложение управляется отдельным `compose.app.yml` (проект `gm-table-app`):

- `client`: Vite на 5173 внутри контейнера; порт хоста по умолчанию 40310.
- `server`: TypeScript через `tsx`, порт 3000 только внутри Docker-сети.
- Без Nginx. Vite проксирует `/api`, `/uploads`, `/socket.io` на `server:3000`.
  Прокси включается через `DOCKER_API_TARGET`; локальный запуск без этой
  переменной сохраняет прежнюю конфигурацию.
- В контейнере клиента `VITE_API_URL` и `VITE_WS_URL` пустые:
  браузер использует адрес открытой страницы.
- Исходники включены в образы. После изменения кода нужна пересборка.
- Сервер получает секреты из корневого `.env` при запуске. Не выводи их в чат
  и не включай `.env` в образы или Git.
- Загрузки хранятся на хосте в `server/uploads` (либо `DOCKER_UPLOAD_DIR`).
- `server-entrypoint.sh` заменяет только hostname и порт копии `DATABASE_URL`
  на Docker-адрес БД; исходный `.env` не меняет.

Команды из корня репозитория:

```sh
docker compose -f compose.app.yml config --quiet
docker compose -f compose.app.yml build
docker compose -f compose.app.yml up -d --wait
docker compose -f compose.app.yml ps
docker compose -f compose.app.yml logs --tail=100 server client
docker compose -f compose.app.yml down
```

Последняя команда останавливает только приложение. Для просмотра сайта можно
пробросить порт 40310 через VS Code и открыть `http://localhost:40310`.

## База данных и намеренное поведение

- БД уже работает в отдельном контейнере `gm-table-postgres`.
- Её Compose — `docker-compose.yml`; сеть — `dnd-site_default`, alias — `postgres`.
  Приложение подключается к этой сети как к внешней.
- Без отдельного задания не меняй конфигурацию, контейнер или данные БД,
  не перезапускай её и не выполняй migrate, reset или seed.
- Сброс онлайн-статусов участников и токенов при старте backend — намеренное
  инженерное решение. Не исправляй его как баг.
- Рисунки и метки в памяти процесса теряются при перезапуске — учитывай это.
- Пользователь считает текущее поведение проекта ожидаемым. Изменяй логику
  только в рамках конкретной задачи; находки сначала объясняй.

## Как работать с пользователем

Общайся по-русски. Работай понятными шагами: коротко объясни действие,
выполни его и сообщи результат проверки. Не запрашивай повторно уже данное
разрешение на тот же объём работы. Сохраняй незакоммиченные изменения;
перед правками проверяй `git status` и нужные diff.
