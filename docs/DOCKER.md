# Прототип в Docker (без Nginx)

Приложение запускается отдельно от существующей БД:
- `client`: Vite, интерфейс и проксирование `/api`, `/uploads`, `/socket.io`.
- `server`: Fastify + Socket.IO, запуск TypeScript через `tsx`.

Это режим для прототипа. Исходники копируются в образы; после изменения кода
нужна пересборка. Nginx и production-сборка здесь не используются.

## Что нужно перед запуском

1. Уже работающий PostgreSQL с существующей схемой и миграциями.
   Конфигурация приложения не создаёт БД и не выполняет миграции или seed.
2. Корневой `.env` с рабочими `DATABASE_URL` и `JWT_SECRET`.
   Секреты передаются серверу при запуске и не копируются в образы.
3. Существующая Docker-сеть `dnd-site_default` с БД под именем `postgres`.
4. Папка загруженных файлов `server/uploads`. Если локальный сервер использует
   другую папку, задай `DOCKER_UPLOAD_DIR` в корневом `.env` её абсолютным путём.
   Отсутствующая папка вызывает ошибку, а не создаётся автоматически.
5. Свободный порт 40310. Если локальный клиент уже работает, задай другой
   `DOCKER_CLIENT_PORT` (например, 40311) в корневом `.env`.

При старте контейнера сервера в копии `DATABASE_URL` меняются только hostname
и порт на `postgres:5432`. Логин, пароль, имя БД и параметры сохраняются.
Сам `.env` не изменяется. Для другой сети доступны `DOCKER_DB_NETWORK`,
`DOCKER_DB_HOST`, `DOCKER_DB_PORT`.

Важно: код приложения при запуске сбрасывает онлайн-статусы участников и
токенов в БД. Это существующее поведение сервера. Не запускай его параллельно
с действующим сервером во время игры. Временные рисунки и метки находятся
в памяти процесса и при перезапуске теряются.

## По шагам

Проверить конфигурацию без вывода секретов:

```bash
docker compose -f compose.app.yml config --quiet
```

Собрать только образы (контейнеры не запускаются, соединения с БД нет):

```bash
docker compose -f compose.app.yml build
```

Запустить приложение, когда готов переключиться с локального сервера:

```bash
docker compose -f compose.app.yml up -d
docker compose -f compose.app.yml ps
docker compose -f compose.app.yml logs --tail=100 server client
```

Открыть `http://<адрес-сервера>:40310` (или порт `DOCKER_CLIENT_PORT`).
Можно пробросить этот порт через VS Code и открыть `http://localhost:40310`.
В браузере API, WebSocket и картинки используют тот же адрес; имя `server`
применяется только для связи контейнеров. Порт backend наружу не публикуется.
При доступе через домен при необходимости настрой список разрешённых хостов
Vite; проверку хоста целиком отключать не нужно.

Остановить только приложение:

```bash
docker compose -f compose.app.yml down
```

В этом Compose нет сервиса PostgreSQL. Его контейнер, конфигурация, каталог
данных и внешняя сеть не управляются этими командами.
Загруженные картинки остаются в папке на сервере.
